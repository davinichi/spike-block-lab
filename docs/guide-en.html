Open SPIKE Block Lab

Build with blocks.
Explore with SPIKE.

SPIKE Block Lab (SBL) is a browser-based programming environment for LEGO SPIKE Prime. Use the Language selector to switch between Japanese and English. Both versions use the same saved project on this browser.

SBL v1.0.0 is the operational release. Feature additions are on hold; bug fixes will continue. Existing project compatibility and stable classroom use take priority. EBL and EBL-RT, including the EBL-RT Windows app, remain in preview development. This release does not mean all hardware features have been verified.

Your first program

  1. Choose a sample or start a new program.
  2. Connect instructions below a Start block. Use the colored categories to find blocks for motors, movement, lights, sound, sensors and control.
  3. Change the numbers and options to express what you want your robot to do.
  4. Use Save to download a .spikelab project. Automatic saving on this device is useful, but a downloaded file lets you keep a separate copy or move to another device.

Connect, transfer and run

Use a regular Chrome or Edge tab on a compatible computer or Chromebook. Turn on the SPIKE Prime hub and open Connect / Transfer. Choose Bluetooth or USB cable. For USB, connect a data-capable cable and close other apps using the hub. Click Connect and select the hub in the browser chooser. Read the connection and device checks shown in SBL before transferring.

Choose a program slot. Transfer saves the program to the hub; Transfer and run saves and starts it. After a successful transfer, the stored program can run on the hub without keeping the browser connected. Disconnecting the browser does not stop a running program.

SBL targets the standard SPIKE Hub OS. The connected hub, motors and sensors must match the ports in your program. English localization does not change the hub firmware or motor behavior.

Read Python next to your blocks

Open Teachers, then View Python. The left pane shows your blocks and the right pane shows the generated Python. Changes to your blocks update the code automatically.

The Your program tab shows the instructions you made; the Internal helpers tab contains support code for the hub. In English mode, automatic explanation comments are in English. Your own names and text stay as you wrote them.

  • Save Python (2 files) downloads a ZIP with program.py, sbl_runtime.py and a README.
  • Save Python for transfer (1 file) downloads the combined program, including its helpers.

The two Python files share a namespace. program.py alone is not a complete program and a normal import of the helper file is not supported. SBL combines them for transfer. The Python view is read-only; edited Python cannot be converted back to blocks.

Reuse your own blocks

Create a My Block from the Teachers menu. Give it a name and, when needed, arguments or return values. Put the reusable instructions inside its definition, then use a call block in your program. Export and import My Blocks to reuse definitions in other projects. Names already used in the destination project must be resolved before import.

Inspect and record

Use sensor blocks for conditions and measurements. Battery-voltage blocks let your program read the hub battery voltage. The connection panel also provides device information and sensor readings where supported. Recording blocks can store measurements on the hub for retrieval as CSV.

Switch languages safely

Switching languages saves and reloads the current project. Block types, connections, numbers, variable names, My Block names and your text are preserved. If automatic saving fails, the switch is cancelled so you can save a file first. If a hub is connected, SBL asks before disconnecting it.

Sample programs may contain Japanese example names or text. These are project content and remain unchanged, just like names in your own projects. The full reference manual and hardware-test checklist are currently available in Japanese from the Teachers menu.

Delete a hub program

Connect by Bluetooth or USB. Open Teacher / Instructor tools and choose Delete a hub program. Select a slot from 0 to 19, check the hub name and slot, then confirm. This cannot be undone; PC project files remain. The standard public protocol does not provide a slot inventory, so occupancy and program names are unknown. Tested with simulated hubs; deletion on physical hardware has not been verified.

Connection buttons

The top Connect and transfer button remains teal. Disconnected status remains gray. Connected status and the Connect action in the connection panel are red. Read the status text and icon to distinguish each state.

Distance-sensor lights and hub motion

Display: set all four distance-sensor lights to 0–100% brightness (0 is off). Sensors: read hub yaw/pitch/roll in degrees, angular velocity on physical X/Y/Z axes in degrees per second, or acceleration in mG (1000mG = 1G, including gravity). Reset heading immediately, or initialize after checking that all three angles vary by no more than 0.5 degrees for one second. The maximum wait is 1.1–30 seconds; timeout reports an error without resetting. Keep the hub stationary. This is a startup reference aid, not internal sensor calibration or continuous drift correction. Hardware behavior is unverified.

Motor-stall sample

The 5-second straight-drive sample monitors left B and right C separately at 20% speed. Every 0.1 seconds it checks whether either encoder has failed to progress by at least 5 degrees for 1 second. It stops both motors before a red light and alert tone. Change ports and thresholds for your robot. Wheel slip with a stationary chassis is not detected. Angle or acceleration integration cannot guarantee translational rest. Hardware behavior is unverified.

Conditional loops

Repeat until stops when its condition becomes true. Repeat while continues only while its condition is true. Both check before the first iteration, so the body may run zero times. Choose the required block in Control; there is no mode dropdown. Existing projects retain their saved until/while condition when loaded and saved again.

Errors and file notifications

Program errors appear above the block editor, and the affected block is marked when it can be identified. The notice clears when the error is fixed. Connection and transfer errors appear beside their controls. File notifications appear beside Save; download-start notices clear after about five seconds, while errors remain visible. Detailed communication logs stay at the bottom.

SBL / EBL common-block import

Open accepts .spikelab and .ev3lab editing files. Review conversion before opening. Hardware-specific or unsupported blocks are retained as red review blocks and prevent generation and transfer, including when disabled or disconnected. Save under a different name (_SBL or _EBL). The source project is embedded and can be recovered using the teacher menu, including after save/reload. Hardware behavior, PID timing and recording limits still differ. Real-device operation is unverified.
